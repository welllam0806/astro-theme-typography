参加搬瓦工新加坡新机测试活动，用家里的联通宽带在晚高峰实测了一圈。结论先放前面：**这是一台"下行很猛、延迟很稳、但往上发很吃力"的机器。**

测试全程从家里的 Debian 12 主机直连测试机，没有经过任何代理或中转，延迟、路由、iPerf3 都是家宽真实出口的数据。

## 一、测试环境

| 项目 | 内容 |
| --- | --- |
| 所在地 | 山东省临沂市 |
| 运营商 | 中国联通（家庭宽带，单流上限约 200 Mbps） |
| 测试机房 | Ultra Singapore（BandwagonHost） |
| 测试时间 | 2026-11-10 21:00 ~ 22:10（晚高峰） |
| 测试机 | KVM / 2 vCPU（AMD EPYC-Genoa 2.9 GHz）/ 2 GB + 1 GB Swap / 38 GB / 无 IPv6 |
| ASN | AS25820 IT7 Networks |

## 二、延迟与丢包：晚高峰稳得不像话

21:52 复测 300 包 ICMP：

- **丢包 0%**
- 平均 **87.23 ms**（86.25 ~ 90.89 ms）
- 抖动 mdev **0.911 ms**

曲线基本是一条直线，看不出晚高峰的痕迹。

不过有个细节值得记一笔：21:15 紧接 iPerf3 上行压测结束测的那一轮 300 包，出现了 **3.67% 丢包**、均值 99.9 ms。也就是说链路本身净空充足，但突发上行大流量时会有短暂的丢包窗口——属于拥挤，不是线路故障。

反向（新加坡 → 家宽）20 包同样 0% 丢包、87.1 ms，双向对称。

## 三、路由：联通用户少见的好回程

**去程**：山东联通 218.59 / 202.102 → 联通 169 骨干 219.158 → 210.14.161 / 218.105 → 202.77.23 → 43.255.170 → IT7（142.0.32.x），末跳 86.9 ms。

**回程**：IT7 → 203.144 新加坡电信 → 69.194 CTGNet → 203.22 CTG → **59.43 电信 CN2** → 219.158 联通 169 → 61.156 / 61.179 山东联通，末跳 86.6 ms。

回程国际段走 **CN2（59.43）**，落地再转联通。对联通用户来说这属于"捡到好回程"。

## 四、测速：下行 778 Mbps，上行 95 Mbps

iPerf3，每项 15 秒、预热 3 秒，家宽直连：

| 方向 | 单线程 | 4 线程 | 重传 |
| --- | --- | --- | --- |
| 上行（家宽 → 新加坡） | **47.8 Mbps** | **95.5 Mbps** | 7596 / 13506 次 |
| 下行（新加坡 → 家宽） | **240 Mbps** | **778 Mbps** | 0 / 6802 次 |

方向性差异非常明确：下行能跑到 778 Mbps，说明机器带宽根本没问题；而上行只有 47.8 / 95.5 Mbps，还带着上万次重传——是"家宽 → 新加坡"这段上行在晚高峰被挤了。

TcpQuality 的国内单线程排行（晚高峰）：

- **广东电信**：回程 426.9 Mbps（54ms）｜去程 605.4 Mbps（54ms）
- **上海电信**：回程 268.6 Mbps（80ms）｜去程 306.6 Mbps（81ms）
- **上海联通**：回程 260.3 Mbps（80ms）｜去程 281.7 Mbps（80ms）
- **北京联通**：回程 257.1 Mbps（84ms）｜去程 377.4 Mbps（81ms）
- **移动系整体偏弱**：北京移动回程 1.0 Mbps（重传 21.97%、559ms）、上海移动 44.6 Mbps（8.78%）、广东移动 39.5 Mbps（8.64%）
- **国际方向（Apple）**：下载 3506.3 Mbps、上传 1659.4 Mbps、15 ms

## 五、实际体验

- **网页首字节**：100 KB 静态页 ×10，TCP 建连 0.087 ~ 0.097 s，首字节 **0.176 ~ 0.195 s**，整页 0.46 ~ 0.58 s，体感接近国内站点。
- **常用服务延迟（自机房发起）**：OpenAI 8.80 ms、YouTube API 8.80 ms、Google 10.91 ms、GitHub API 12.74 ms、X 13.11 ms、Cloudflare cdnjs 4.79 ms、Steam 5.99 ms；Telegram 160 ms、Gmail 223 ms、Netflix API 178 ms。
- **亚太互连**：香港 30 ms（725 / 1075 Mbps）、新加坡本地 6517 / 7222 Mbps；洛杉矶 168 ms、法兰克福 147 ms、阿姆斯特丹 157 ms、圣保罗 332 ms。
- **流媒体 / AI 解锁**：TikTok、Disney+、Netflix（DNS 解锁）、YouTube 原生解锁 [SG]，**ChatGPT 原生解锁 [SG]**；Amazon Prime Video、Reddit 屏蔽。
- **硬件**：GB5 单核 1221 / 多核 2287，Sysbench CPU 4221.87 / 8194.57，磁盘 RND4K Q1 读 25.9 MB/s（6.6k IOPS）、Q32 读 437 MB/s（112k IOPS），SEQ1M Q1 读 1724 / 写 3080 MB/s。轻量业务够用。

## 六、需要注意：IP 风险评分分歧很大

Maxmind 把城市标成加州洛杉矶，实际使用地 [SG]、注册地 [CA] 加拿大，属**广播 IP**；五个库一致判定为机房 IP。

风险评分则分歧明显：Scamalytics 0（低）、AbuseIPDB 0（低），但 **IP2Location 99（高风险）**、**IPQS 75（可疑 IP）**、ipapi 1.17%（较高），部分库把它标成代理 / VPN。注册风控严格的服务（银行、部分电商、部分 AI 试用）可能会挑 IP，建议自行验证。

邮局方面：本地 25 端口出站可用，Gmail / Outlook / Yahoo / Apple 通；423 个黑名单库中 47 个已标记、0 个进黑名单。

## 七、总结

**亮点**：晚高峰联通回程 4837 / CTGGIA + CN2 国际段，0% 丢包、91~93 ms、抖动 <1 ms；下行 240 / 778 Mbps 充沛；新加坡本地与东南亚互连顶级；ChatGPT / Netflix / YouTube 原生解锁，AI 站点直连 8~13 ms。

**短板**：上行 47.8 / 95.5 Mbps 且重传上万次；移动用户回程绕行、丢包 8%~22%；国内 6 个测速节点全部 ERROR（脚本侧节点不可用）；IP 在 IP2Location / IPQS 属高风险档。

**适合**：亚太落地、AI 服务与流媒体解锁、轻量建站与反代、追求"联通好回程"的用户。
**不适合**：大文件上行（备份、图床、视频回传）、以移动宽带为主的用户。

一句话：**下行和延迟是这台机的强项，晚高峰稳得像一条直线；但"往上发"这件事在新加坡方向被卡住了，上传需求重的慎选。**
